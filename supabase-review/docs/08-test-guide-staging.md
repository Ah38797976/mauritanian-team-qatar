# 08 — دليل اختبارات PostgreSQL/RLS على staging (غير مُنفَّذة)

> كُتبت وفُحصت **نصيًا فقط** (توازن الأقواس، المتغيرات، البنية، وبحث طفرة عن العيوب المعروفة). **لم تُشغَّل ولا مرة** على Postgres.
> توقّع أن يظهر في أول تشغيل خطأ أو اثنان في الاختبارات نفسها (أسماء أعمدة، سلوك pgTAP على Supabase)؛ يُصحَّح الاختبار فقط إذا ثبت أن الخطأ في الاختبار لا في الشيفرة، ويُسجَّل ذلك.

## المتطلبات
مشروع staging منفصل (G2) + بيانات وهمية فقط + `create extension if not exists pgtap with schema extensions;` + 7 مستخدمي اختبار في Auth + تطبيق `0001→0007` (G3).

## المجموعات وما يجب أن تُثبته
| الملف | يتطلب | الغرض (ما يجب أن يثبته) |
|---|---|---|
| `00_catalog_security.sql` | 0001–0006 فقط | الإغلاق الافتراضي: RLS على كل جدول وسياسة SELECT واحدة له، لا سياسات كتابة، anon بلا أي امتياز، authenticated SELECT فقط (جدول وأعمدة وsequences)، EXECUTE على 17 RPC بالضبط، كل definer بـ `search_path` فارغ، لا Views ولا Realtime، سلامة المشغّلات. |
| `rls_matrix.sql` (موجود، أُضيف له search_path) | 0001–0007 | مصفوفة الأدوار: مدرب/مسؤول مباراة/أمين مالي/أمين رياضي/إدارة/مؤسس على الجداول والـRPC. |
| `20_contact_leak.sql` | 0001–0007 | **لا يرى أحد بلا صلاحية أي هاتف/بريد** (جداول + مخرجات RPC + ربط)، تغيّر الصلاحية فوري، **لا قناة تخمين** (لاعب وطاقم)، السجل لا يحمل القيم. فيه ضوابط إيجابية حتى لا يكون الاختبار فارغًا. |
| `30_session_and_escalation.sql` | 0001–0007 | الهوية من الجدول لا من claims، غريب/معطّل/تغيّر دوره، لا كتابة مباشرة لأحد، غير المؤسس لا يغيّر الصلاحيات، القواعد الصلبة (مسؤول المباراة/مؤسس واحد)، نطاق مسؤول المباراة، ثبات السجل. |
| `40_cross_team.sql` | 0001–0007 | عزل فريق ثانٍ (يُنشأ داخل الاختبار ويُلغى): لا قراءة، لا كتابة عبر معرّفات، عضوية في فريقين تُحسم للأقدم، **وإظهار الحد المعروف S-9**. |
| `50_storage.sql` | 0005 + 0007 | حاوية خاصة بحد 2MB وأنواع مسموحة، قراءة/رفع/حذف حسب الدور وداخل مجلد الفريق، شكل المسار، لا تعديل. |

## التشغيل
```bash
export STAGING_DB_URL='postgresql://…'      # من مدير أسرارك، لا من ملف في المستودع
export CONFIRM_STAGING='<project-ref>'
export SEED_U_FOUNDER=… SEED_U_ADMIN=… SEED_U_SECRETARY=… SEED_U_COACH=… SEED_U_OFFICER1=… SEED_U_OFFICER2=… SEED_U_TREASURER=…
bash supabase-review/sql/tests/run_staging_tests_ONLY.sh            # تجريبي: يطبع فقط
bash supabase-review/sql/tests/run_staging_tests_ONLY.sh --execute  # فعلي (بعد G3 فقط)
```
كل ملف داخل معاملة تنتهي بـ `rollback` فلا يبقى أثر. السكربت يرفض العمل دون تأكيد مرجع المشروع ويرفض روابط تبدو إنتاجية.

## معيار القبول (بوابة G3)
كل المجموعات بلا `not ok`؛ ومخرجات `diag` في 00 تُراجع يدويًا؛ ولا اختبار يُعدَّل لإنجاح صوري.

## ما لا تغطيه (قائمة يدوية)
1. «Exposed schemas» في لوحة API = `public` فقط؛ تعطيل Sign-ups وAnonymous sign-ins؛ تفعيل MFA؛ سياسة كلمات المرور وحدّ المحاولات.
2. `get_advisors` (الأمان والأداء) بلا تحذيرات حرجة.
3. رفع صورة حقيقية: رفض >2MB والأنواع الخاطئة، انتهاء الرابط الموقّع، ملف مزيّف الامتداد.
4. اختبار الواجهة المتصلة (Playwright) لكل دور مقابل staging؛ CSP؛ XSS.
5. اختبار حمل خفيف لسياسات RLS (دوال تُستدعى لكل صف).
6. أي سلوك للنسخة الحالية من Supabase مخالف لافتراضات الوثائق (انظر خطر 11 في وثيقة 04).
