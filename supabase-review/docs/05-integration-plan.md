# 05 — خطة الربط للمراجعة (المرحلة 1) — لا تنفيذ

> نتيجة فحص ساكن (قراءة فقط) لتوافق تصميم القاعدة مع الواجهة. لم يُنفَّذ SQL ولم يُتصل بأي خدمة.
> «تطابق» هنا يعني تطابقًا في **القراءة النصية للكود**، لا أنه جُرّب.

## 1) توافق الجداول والصلاحيات مع وظائف الواجهة
| الوظيفة في الواجهة (`Store.*`) | المقابل في SQL | الحالة |
|---|---|---|

| `savePlayer/delPlayer/unregisterPlayer` | `rpc_save_player/delete_player/unregister_player` | مطابق: حدود الحقول، رفض الهاتف/البريد لغير المخوّل، سياسة الحذف |
| `saveStaff/delStaff` | `rpc_save_staff/delete_staff` | مطابق (لا بريد للطاقم) |
| `saveMatch/addEvent/setResult` | `rpc_save_match/add_event/set_result` | مطابق، ومسؤول المباراة لمبارياته فقط |
| `setStarters/setAtt` | `rpc_set_starters/set_attendance` | مطابق (حد 11 + نشط فقط عند الإضافة) |
| `setPerm/saveTeam` | `rpc_set_permission/save_team` | مطابق (الأدوار للمؤسس فقط) |
| `statRows/topScorers` | `rpc_get_stat_rows` | الترتيب أهداف ↓ مشاركات ↓ اسم؛ **الهداف/التعادل يُحسب في الواجهة** من الصفوف |

أعداد البذرة `0007` طابقتُها يدويًا مع `data.js`: 12 لاعبًا، 4 طاقم، 3 مباريات، 6 أحداث، 19 مشاركة، 24 حضورًا.

## 2) ما وُجد وما يلزم قبل أول تشغيل
| # | البند | الخطورة | الإجراء |
|---|---|---|---|
| F-1 | `rpc_get_stat_rows` كان يستخدم متغيرًا اسمه `full` وهو كلمة محجوزة في PostgreSQL (FULL: reserved, can be function or type حسب التوثيق الرسمي) → كان إنشاء الدالة سيفشل | عالية (كانت ستوقف 0004) | **أُصلح** بإعادة تسميته `v_full` (7 مواضع، انظر `phase1-results/0004_rpc_fix.diff`). لم يُجرَّب لعدم وجود Postgres هنا |
| F-2 | المحوّل `supabase-adapter.js`: الحصص تُرجَع بحقل `session_date` بينما الواجهة تقرأ `date` | متوسطة | يُصحَّح عند الربط (في فرع منفصل) |
| F-3 | المحوّل لا يضع `teamId` في الطاقم/اللاعبين، ولا يدمج هاتف/بريد اللاعب في الكائن (الواجهة تتوقعه في `player.phone/email`) | متوسطة | دمج `cache.contacts` في عرض اللاعب عند الربط |
| F-4 | قائمة «مسؤول المباراة» في نموذج المباراة تقرأ `S.users` الخام؛ لا يوجد في المحوّل قراءة لأعضاء الفريق | متوسطة | استعلام `team_members` (سياسة `members_read` تسمح لمن يملك `matches`) |
| F-5 | `Store.roster()` للمسؤول يُرجع `[]` في النموذج، بينما `rpc_get_roster()` يُرجع لاعبي مبارياته | منخفضة | قرار صياغة عند الربط: تبقى `roster()` للقوائم العامة، وتُستخدم قائمة النطاق لأحداث المباراة |
| F-6 | `app.js` يقرأ الحالة الخام `S` في 21 موضعًا (`S.players, S.matches, S.lineup, S.users, S.sessions, S.att, S.perms, S.cur`) ويفترض قراءة متزامنة | **جوهرية** (تغيير بنيوي) | لا تُعدَّل الآن. تُنفَّذ في فرع خلف علم بعد G4: كل قراءة عبر `TeamData.cache()` وكل كتابة `await` |
| F-7 | مبدّل المستخدم التجريبي (`#userSel`, `Store.setUser`) يجب ألّا يوجد في أي نسخة متصلة | عالية عند الربط | يُحذف في نسخة الربط ويُستبدل بتسجيل دخول |
| F-8 | شريط التنقل يعرض كل الصفحات لكل دور (الصفحة تُرفض) | منخفضة | تصفية الروابط حسب الصلاحية في نسخة الربط؛ وهي ليست حماية |
| F-9 | `audit_log` ممنوع الحذف بـ Trigger، وحذف فريق (`on delete cascade`) سيفشل بسببه؛ وحذف مستخدم هو مسؤول مباراة سيفشل بسبب المفتاح الأجنبي | منخفضة | سلوك مقبول لفريق واحد؛ يُقرَّر إجراء «إيقاف/نقل» بدل الحذف لاحقًا |
| F-10 | ملاحظة README عن «اختبار يفشل عمدًا» قديمة (النتيجة الفعلية 157/157) | منخفضة | **لم أعدّل README النموذج** (حفاظًا على النسخة بايتًا ببايت)؛ مذكور هنا وفي التقرير |
| F-11 | `revoke … on all functions in schema public` عام | متوسطة | يُستبدل بقائمة صريحة عند التطبيق (ورد في وثيقة المخاطر 04) |

## 3) المفاتيح والإعدادات (ما جُهّز)
- `supabase-review/.env.example`: قالب بقيم وهمية فقط. الواجهة موقع ثابت ولا تقرأ `.env`، فالقيم العامة تُنسخ يدويًا إلى `client/config.js` لاحقًا.
- `.gitignore`: يمنع رفع `.env*` و`client/config.js` والمفاتيح.
- `tools/scan_secrets.py`: فحص محلي لأنماط `sb_secret_`/`sbp_`/JWT/سلاسل الاتصال. نتيجته على الحزمة: لا أنماط مشبوهة.
- المحوّل يرفض `sb_secret_*` وأي JWT دوره غير `anon`. هذا فحص **عميل** مساعد فقط وليس حماية؛ الحماية الفعلية RLS/RPC.

## 4) مسار الربط الأبسط الآمن (بعد موافقتك فقط)
1. **G2** مشروع staging منفصل (قرار: المنطقة والخطة) + تعطيل التسجيل العام + تفعيل MFA للمؤسس/الإدارة.
2. **G3** تطبيق `0001→0006` خطوة بخطوة بعد مراجعتك لـ F-1/F-11، ثم `0007` وبعده `rls_matrix.sql`، مع نتيجة كل خطوة قبل التالية.
3. التحقق من `get_advisors` (الأمان) في Supabase ومن إعدادات Data API (المخطط `app` غير معروض).
4. **G4** فرع واجهة متصلة: إصلاح F-2…F-8، تحميل supabase-js **بإصدار مثبّت**، CSP صارمة، تشغيل Playwright مقابل staging.
5. **G5** مراجعة أمنية مستقلة. **G6** لا بيانات حقيقية قبل مراجعة قانونية وموافقات الأفراد.

## 5) ما لا يجوز ادعاؤه الآن
- لم يُشغَّل أي SQL ولم يُفحص بمحلل Postgres (لم يتوفر مثبّت الحزم ولا Postgres في هذه البيئة)؛ فقط فحص ساكن يدوي وآلي بسيط.
- RLS/RPC **غير مختبرة**. `rls_matrix.sql` لم يُشغَّل.
- المحوّل **غير مُحمَّل** ولم يُجرَّب مع supabase-js.
