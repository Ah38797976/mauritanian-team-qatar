## 3) استخدام revoke العام — ما يحتاج صلاحيات صريحة
**قبل:** `revoke all on all functions in schema public from public, anon` (0004) و`… in schema app …` (0002).
**المشكلة:** (أ) يعتمد على ما هو موجود وقت التشغيل، فأي دالة تُضاف لاحقًا في المخطط تبقى ممنوحة افتراضيًا (إعدادات Supabase تمنح EXECUTE لـ anon/authenticated/service_role)، (ب) لا يسحب من `authenticated` إطلاقًا، (ج) قد يمسّ دوال لا تخصنا في `public`.
**بعد (مطبّق):**
- `public`: `revoke all on function <17 توقيعًا صريحًا> from public, anon` ثم `grant execute … to authenticated` للـ17 فقط؛ و`alter default privileges … revoke execute on functions from public, anon, authenticated` ليحتاج أي دالة مستقبلية منحًا صريحًا.
- `app`: `revoke all on function <13 دالة صريحة> from public, anon, authenticated` ثم منح 9 دوال فقط لـ authenticated (يحتاجها تقييم السياسات): `has_perm, role_has_perm, my_role, my_team, can_see_roster, can_view_matches, can_read_match, try_uuid, deny`.
- **تبقى بلا منح لأي دور:** `app.log` و`app.seed_team_defaults` و`app.lineup_guard` و`app.audit_immutable` و`app.touch_updated_at` (الـ Triggers لا تحتاج EXECUTE عند التنفيذ).
- الجداول: `revoke all on all tables in schema public from anon, authenticated` يبقى مقبولًا لأن المشروع مخصص لهذا التطبيق؛ يُعاد تقييمه لو شارك المشروع تطبيقًا آخر.

## 4) تحديد المستخدم والدور من جلسة المصادقة
- الهوية: `auth.uid()` ← `sub` في JWT الذي توقّعه Supabase. الدور: `team_members.role` فقط (`active=true`) عبر `SECURITY DEFINER` بـ `search_path=''`. لا يُقرأ أي claim قابل للتعديل (`user_metadata`).
- الفريق: `app.my_team()` (الأقدم عضويةً)؛ الواجهة لا ترسل team/role/actor. ✔
- الإبطال الفوري: تعطيل العضوية أو تغيير الدور يسري في الطلب التالي دون انتظار انتهاء JWT. ✔ (مختبر في 30)
- ثغرات متبقية: S-2 (AAL2)، S-3 (الدعوات)، S-10 (إعدادات Auth).
