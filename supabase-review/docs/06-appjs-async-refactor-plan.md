# 06 — خطة إعادة هيكلة `app.js` للقراءة غير المتزامنة (للمراجعة — لا تنفيذ)

> لم يُعدَّل `app.js` ولا `store.js` في هذه المرحلة. التغيير بنيوي فيُشرح هنا قبل تنفيذه بموافقتك.

## المبدأ الحاكم
1. **النموذج الحالي يبقى كما هو ويعمل**: `Store` في الذاكرة يبقى متزامنًا (الاختبارات تستدعي `Store.*` وتتوقع نصًا فوريًا).
2. `app.js` يصير **محايدًا للخلفية**: القراءة من نسخة مخبأة متزامنة (cache) والكتابة بـ `await` (الانتظار على نص عادي يعمل كما هو).
3. النسخة المتصلة **ملف HTML منفصل** (`index.connected.html`) وفرع منفصل؛ `index.html` الأصلي لا يتغير ولا يحمّل أي ملف Supabase.
4. كل مرحلة تُقبل فقط إذا نجحت الاختبارات الـ337 دون تعديل، ثم اختبارات جديدة للمرحلة.

## مخاطر ونقاط انتباه
- `St.on(render)` يُستدعى بعد كل كتابة؛ في المتصل يصدر بعد `refresh()` فقط (انظر تسلسل الكتابات في المحوّل v2) لمنع عرض حالة نصفية.
- سباق: نقرتان متتاليتان ⇒ كتابتان؛ المحوّل v2 يسلسل الكتابات، والواجهة تعطّل الأزرار.
- أخطاء الشبكة: الرسالة العربية الموحدة، دون كشف نص خطأ Postgres.
- `listeners` على `hashchange` لا تستدعي القراءة قبل جاهزية الـ cache؛ تُعرض شاشة تحميل.
- لا يُنقل منطق الأمان إلى الواجهة: كل ما يخص الصلاحيات يبقى تحسينًا لتجربة المستخدم، والخادم هو الفيصل.
