# 01 — تصميم قاعدة البيانات (فريق واحد، جاهزة لتعدد الفرق)

## المبادئ
- **قاعدة واحدة للفريق**، وكل جدول يحمل `team_id` مع مفاتيح أجنبية مركّبة `(team_id, id)` حتى لا يرتبط سجل بفريق آخر.
- **الأدوار والصلاحيات في جداول** (`team_members`, `role_permissions`) لا في بيانات المستخدم القابلة للتعديل.
- **فصل الخصوصية بالجدول**: RLS تعمل على مستوى الصف لا العمود، لذلك فُصل ما يحتاج صلاحية أعلى في جدول مستقل:
  `players` (الأساسي + المدينة) ← `player_contacts` (هاتف/بريد)، و`staff_members` ← `staff_contacts` (هاتف فقط).
- **رموز إنجليزية في القاعدة وتسميات عربية في الواجهة** (جدول التحويل في `client/supabase-adapter.js`).
- **أهدافنا في المباراة مشتقة** من أحداث «هدف» (لا عمود مخزَّن)، كما في النموذج، فلا يحدث عدم اتساق. أهداف الخصم عمود `opp_goals`.

## الجداول
| الجدول | المقابل في النموذج | ملاحظات |
|---|---|---|
| `teams` | `DATA.teams` | الاسم/المدينة/اللون/سنة التأسيس |
| `team_members` | `DATA.users` | `user_id` من `auth.users` + الدور؛ مؤسس واحد فعّال لكل فريق (فهرس فريد) |
| `permission_catalog`, `role_permissions` | `DATA.perms`, `Store.MODS` | `roles` ليست صلاحية قابلة للمنح: للمؤسس حصرًا. قيد CHECK يمنع منح مسؤول المباراة أي صلاحية طاقم |
| `players` | `DATA.players` | رقم القميص فريد بين غير «غير المسجّلين» (فهرس جزئي) |
| `player_contacts` | `phone/email` | صلاحية `contactPlayers` فقط |
| `player_photos` | — (جديد) | بيانات وصفية؛ الملف في Storage الخاص؛ ≤ 2MB؛ jpg/png/webp؛ صورة رئيسية واحدة |
| `staff_members`, `staff_contacts` | `DATA.staff` | لا بريد للطاقم في أي بنية |
| `lineups`, `lineup_starters` | `DATA.lineup` | حد 11 وقبول «نشط» فقط عند الإضافة (Trigger) |
| `training_sessions`, `attendance` | `DATA.sessions/att` | حضور لاعب «غير مسجّل» مرفوض في RPC |
| `matches`, `match_players`, `match_events` | `DATA.matches` | الدقيقة 1–130؛ الحدث يتطلب مشاركة اللاعب؛ حذف لاعب له مشاركات مقيّد (`restrict`) |
| `audit_log` | `DATA.logs` | إضافة فقط (Trigger يمنع التعديل والحذف)، ولا تُسجَّل قيم الهاتف/البريد |

## سياسات النموذج المنقولة كما هي
- حذف اللاعب: نهائي فقط بلا أحداث ولا مشاركات؛ وإلا «إلغاء التسجيل» (يبقي التاريخ ويُخرجه من التشكيلة).
- مسؤول المباراة: يرى مبارياته فقط ولاعبيها؛ لا طاقم ولا سجل ولا مؤشرات فريق.
- الأمين المالي: أسماء اللاعبين فقط، **ولا وحدة مالية** (لا جداول اشتراكات/مبالغ؛ لم تُضف عمدًا).
- الهداف والتعادل وترتيب الإحصاءات: تُحسب في `rpc_get_stat_rows()` بنفس الترتيب (أهداف ↓، مشاركات ↓، اسم).

## فجوات معلنة (غير موجودة في النموذج فلم تُبنَ)
- لا شاشة لإنشاء/تعديل **الحصص التدريبية** (توجد في البيانات فقط)؛ في القاعدة ستُنشأ بالبذرة أو بـ RPC لاحقًا بعد موافقتك.
- لا إدارة **أعضاء الفريق/الدعوات** في الواجهة؛ تُصمَّم عبر Edge Function (انظر 02).
- لا حدث «استبدال» ولا تشكيلات متعددة؛ تشكيلة واحدة للفريق.
